# Отклик

Мобильная лента платных исследований с отдельными личными кабинетами. React + Fastify + MongoDB, Telegram через пользовательскую сессию, подбор через ProxyAPI, PWA и ежедневный Web Push.

Извлечение условий и поиск повторов выполняются один раз для общего каталога. Затем ИИ оценивает каждое исследование отдельно по анкете и предпочтениям каждого пользователя. Подходящее нескольким людям объявление появляется у каждого; этапы участия, заметки, скрытия и отказы независимы. Объявления с явным несовпадением сохраняются для личной переоценки, но не показываются в новой ленте.

## Аккаунты

При первом запуске обновления существующий кабинет становится аккаунтом **Денис**. Для входа используй имя `Денис` и прежний пароль из setup. Анкета, карточки, статусы, отказы, подписки и подключения сохраняются. Миграция запускается автоматически до работы API и worker, защищена блокировкой и допускает повтор после прерывания. `OWNER_PASSWORD_HASH` используется только при создании Дениса; повторная миграция не меняет его пароль.

Регистрация открыта со страницы входа: уникальное имя и пароль от 12 символов, без почты. Регистр, лишние пробелы и Unicode-варианты имени не создают разные аккаунты. После регистрации заполни анкету. Лента начинается пустой: доступны только исследования, впервые собранные после регистрации; повтор старого объявления не переносит старый каталог.

Переключатель аккаунтов находится в верхней панели и работает также на телефоне. «Добавить аккаунт» позволяет войти в другой кабинет или зарегистрироваться. После первого входа переключение не требует пароля до выхода или истечения 30-дневной сессии. Можно выйти из текущего или всех аккаунтов на этом устройстве. Список переключателя содержит только сохранённые входы этого браузера; пароли и токены не хранятся в localStorage. Переключение синхронизируется между вкладками.

Только Денис управляет общим Telegram, источниками, расписанием, запуском и отменой сбора. У каждого пользователя свои анкета, предпочтения, карточки, время уведомлений и сводки. Ручное добавление создаёт карточку только в текущем кабинете. Push-подписка браузера относится к активному кабинету и перепривязывается при переключении; ссылка уведомления открывает соответствующий аккаунт (при необходимости нужно войти).

Персонализация использует общий `MAX_AI_CALLS_PER_RUN`. При лимите или ошибке извлечённые объявления остаются в каталоге, а незавершённые личные оценки продолжаются при следующем сборе. Кабинеты обслуживаются по очереди с сохранением позиции. Изменённая анкета переоценивает только личные карточки на этапе «Новое»; разовые причины занятости не становятся предпочтениями.

Причина «Сегодня не успеваю» — разовая: она сохраняется в истории отказов, но не передаётся ИИ как предпочтение и не может стать постоянным запретом.

## Быстрый просмотр

```powershell
npm install
npm run dev
```

Открой http://localhost:5173. Без `MONGODB_URI` запускается **локальный деморежим**: вымышленные предложения, профиль и источники. Можно проверить ленту, скрытие с причиной, этапы работы, анкету, регистрацию и переключение аккаунтов. Демо хранится в памяти и сбрасывается при перезапуске API. Вход в деморежиме не нужен; API доступен только на loopback. Настоящий сбор в деморежиме не запускается.

```powershell
npm test
npm run build
```

С настоящей MongoDB локальный сервер сам обрабатывает очередь каждые 15 секунд, отдельно запускать worker для ручного сбора не нужно. На VPS worker запускается отдельным контейнером.

После сборки `npm start` отдаёт клиент и API с http://localhost:3001 (для изменения данных задай соответствующий `APP_ORIGIN`). PWA/service worker проверяется на собранной версии, а не на Vite dev server.

В ленте кнопка «Добавить» открывает ручное добавление без ИИ: тема, текст, оплата, длительность, формат, город, варианты времени и ссылка. Опрос появляется за сегодня с пометкой «Добавлено вручную» и не переоценивается автоматическим сбором.

По умолчанию сбор запускается ежедневно в 03:00 и дополнительно в 21:00 МСК. Оба времени редактируются в настройках расписания. Вечерний сбор проверяет последние 24 часа независимо от утреннего и не повторяет обработанные сообщения. После обновления правил сравнения городов ранее отклонённые новые карточки будут переоценены при ближайшем сборе; метро и адрес после названия города больше не считаются другим городом.

## Что заполнять в .env

В проекте есть готовый файл `.env`. Для новой копии проекта скопируй `.env.example` в `.env`. Значения вставляются после знака `=`, строки раскомментировать не нужно.

| Поле | Что вставить |
| --- | --- |
| `MONGODB_URI` | Твою полную ссылку MongoDB с логином и паролем. |
| `PROXYAPI_KEY` | API-ключ из https://console.proxyapi.ru. |
| `AI_MODEL` | Можно оставить `openai/gpt-4.1-mini`. |
| `TELEGRAM_API_ID` | Числовой **App api_id** со страницы https://my.telegram.org/apps. |
| `TELEGRAM_API_HASH` | **App api_hash** с той же страницы. Это не код входа. |
| `APP_ORIGIN` | Локально оставить `http://localhost:5173`; на VPS указать `https://твой-домен` без / в конце. |
| `DOMAIN` | На VPS — домен без https://. Локально оставить пустым. |

Потом выполни:

```sh
npm run setup
```

Команда попросит придумать и повторить пароль для входа на сайт (минимум 12 символов). В обычном терминале ввод скрыт. Она сама создаст `.env.secrets` с хешем пароля, ключом шифрования и ключами уведомлений. **Вручную этот файл заполнять не нужно.** Повторный запуск сохраняет существующие ключи и пароль. Оба env-файла исключены из Git и Docker image.

Номер Telegram, одноразовый код и пароль 2FA вводятся позже на самом сайте. Их не нужно добавлять в env.

## Развёртывание на VPS

Нужны Docker Compose, домен с A-записью на VPS и открытые порты 80/443. MongoDB подключается по твоей ссылке; контейнер БД не запускается. Аккаунту MongoDB нужны права чтения и записи в выбранную базу, а VPS — сетевой доступ к кластеру.

1. Заполни `.env` по таблице выше и выполни `npm run setup`.
2. Запусти `docker compose up -d --build`. Коллекции создаются автоматически; перенос существующего кабинета выполняется при запуске. Worker стартует после успешной проверки API и соединения с MongoDB. Caddy получает HTTPS-сертификат.
3. Открой домен, войди с придуманным паролем. Заполни анкету, подключи Telegram в настройках и добавь каналы в разделе «Источники»: по публичной ссылке или через «Выбрать из Telegram». Список включает открытые и закрытые каналы аккаунта, в том числе архивированные. Также доступны группы, супергруппы и личные чаты. Собираются только явно добавленные источники; автоматического вступления нет.
4. Проверь ИИ кнопкой в подключениях, запусти ручной сбор, установи PWA и включи уведомления на нужных устройствах.

Имя базы берётся из пути URI, например `/otklik`; без имени используется `otklik`. При необходимости его можно переопределить дополнительной переменной `MONGODB_DB_NAME`. Параметры вроде `MAX_AI_CALLS_PER_RUN`, `MAX_MESSAGES_PER_SOURCE`, `PROXYAPI_BASE_URL` и `PORT` уже имеют значения по умолчанию — добавлять их не нужно. VAPID Subject автоматически берётся из `APP_ORIGIN`.

Сессия Telegram шифруется AES-256-GCM; код и пароль 2FA не сохраняются. Не меняй ключ шифрования в `.env.secrets` без переподключения Telegram. Не открывай API напрямую в интернет в обход Caddy. Sites/Cloudflare Workers не подходят для этого MTProto worker; нужен обычный VPS.

## Развёртывание в Dokploy

1. Локально выполни `npm run setup`. Если уже выполнял — используй существующий `.env.secrets`: повторно создавать ключи не нужно.
2. В проекте Dokploy создай сервис **Docker Compose**, подключи репозиторий и укажи **Compose Path**: `compose.dokploy.yaml`. Этот вариант содержит app и worker; HTTPS обслуживает Dokploy.
3. В **Environment** вставь содержимое локального `.env`, затем добавь все четыре строки из `.env.secrets`: `OWNER_PASSWORD_HASH`, `ENCRYPTION_KEY`, `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`. Кавычки у значений можно сохранить. Отдельный файл `.env.secrets` на сервере не требуется.
4. Там же замени `APP_ORIGIN` на `https://твой-домен` без завершающего `/`. `DOMAIN` для Dokploy не нужен. Остальные заполненные значения MongoDB, ProxyAPI и Telegram сохрани.
5. Создай DNS A-запись домена на IP сервера. В **Domains → Add Domain** укажи домен, сервис **app**, **Container Port 3001**, путь `/`, включи HTTPS и сертификат Let's Encrypt.
6. Нажми **Deploy**. После изменения домена или переменных снова выполняй Deploy. Открой сайт и войди с паролем, заданным при локальном setup; Telegram подключается через интерфейс сайта.

Публиковать порт 3001 на хосте не требуется. Worker работает внутри Compose без отдельного домена. Сохраняй исходные ключи при обновлениях, чтобы продолжали работать Telegram-сессия и push-подписки.

Документация Dokploy: [Environment для Compose](https://docs.dokploy.com/docs/core/docker-compose), [Domains для Compose](https://docs.dokploy.com/docs/core/docker-compose/domains).

### MTProto-прокси для Telegram

При необходимости добавь в `.env` (в Dokploy — в Environment) одну переменную со ссылкой своего прокси целиком:

```env
TELEGRAM_PROXY_URL="tg://proxy?server=proxy.example.com&port=443&secret=ТВОЙ_SECRET"
```

Также принимается ссылка `https://t.me/proxy?server=…&port=…&secret=…`. После изменения перезапусти приложение и worker; в Dokploy выполни Deploy. Прокси применяется к входу в Telegram, загрузке списка чатов и всему ручному/ночному сбору. Пустое значение означает прямое соединение. Существующую Telegram-сессию переподключать не требуется. Поддерживаются обычные, `dd` и `ee` (fake TLS) секреты библиотеки teleproto. Если заданный прокси недоступен, автоматического переключения на прямое соединение нет. MongoDB и ProxyAPI используют собственные прямые соединения.

## Как работает подбор

- По умолчанию сбор в 03:00 и 21:00, уведомление в 08:00, часовой пояс Europe/Moscow; время меняется в интерфейсе.
- Ночной сбор всегда ограничен последними 24 часами. Даже после простоя сервера он не захватывает более старые сообщения или незавершённый ручной период.
- Кнопка «Собрать» в ленте запускает ручной сбор за сутки, 3, 7, 30 дней или любое целое число от 1 до 30. Границы фиксируются при запуске; ночное расписание не меняется.
- В «Состоянии» показываются текущий источник и этап ИИ, счётчики сообщений и предложений, время запуска. Во время сбора статус обновляется каждые 3 секунды. Один запуск ограничен 10 минутами, ожидание одного ответа Telegram/ИИ — 90 секундами. По таймауту запросы прерываются, сбор останавливается без автоматического повторного запуска; сохранённые результаты остаются, ручной запуск можно продолжить.
- «Отменить сбор» в окне состояния снимает запуск с очереди или передаёт отмену worker через MongoDB. Worker проверяет отмену раз в секунду и прерывает ожидающий запрос Telegram/ИИ. Уже сохранённые сообщения и предложения остаются.
- В «Подключения → Telegram → Проверить соединение» выполняется реальный запрос к Telegram с настроенным MTProto-прокси или напрямую, с ограничением 15 секунд. Проверка доступна и до входа в аккаунт; после входа дополнительно проверяется сохранённая сессия.
- Большие каналы читаются страницами, исходные сообщения сохраняются до обращения к ИИ. При лимите или ошибке у ручного запуска появляется «Продолжить незавершённый сбор»; продолжение использует тот же период и свои позиции чтения. Дубликаты не создаются.
- ИИ извлекает отдельные исследования в JSON, затем отдельно сравнивает с профилем каждого пользователя и его последними 60 содержательными причинами отказов. Даты и города проверяются также кодом. Неизвестные требования дают «Нужно уточнить».
- Минимальная оплата, формат, длительность и обычные отказы — мягкие пожелания. Постоянное условие пользователь вводит и подтверждает явно. Его интерпретирует модель; это не математическая гарантия отбора. Удаление/редактирование причин меняет контекст следующего подбора, включая переоценку ещё новых предложений.
- Дедупликация консервативная: совпадение ссылки/подписи, темы и времени. Сомнительные объявления остаются раздельными. Одинаковые объявления из разных каналов сохраняют все источники. Стадии и заметки не сбрасываются при переобработке.
- `MAX_AI_CALLS_PER_RUN` (100) ограничивает логические обращения к модели; SDK может один раз повторить неуспешный запрос. `MAX_MESSAGES_PER_SOURCE` (500) ограничивает страницу Telegram. Эти значения — ограничения объёма, а не рублёвый бюджет. Расходы проверяются в ProxyAPI.
- Ошибки источников видны в настройках, частичная/неудачная подборка отличается от пустой. Необработанные сообщения сохраняются; последующий запуск обрабатывает только те, которые входят в его период. После аварии задания восстанавливаются, после трёх аварий нужен ручной повтор.
- Push пытается доставиться один раз в день на подписку, включая пустой результат. Метка отправки сохраняется до запроса push-сервису, чтобы избежать повторного уведомления при аварии. Поэтому при ошибке доставки этот день может быть пропущен. Отображение уведомления зависит от устройства, сети и разрешений.

При отключении Telegram приложение удаляет свою сохранённую сессию. Для отзыва доступа также можно завершить соответствующий сеанс в настройках Telegram.

## Интерфейс

Лента по дням → «В работу» → сохранён / откликнулся / записан / прошёл / оплачен. Дата и заметка редактируются отдельно, фактическая оплата учитывается только после стадии «Оплачен». Запись у организатора выполняется вручную по исходной ссылке.

Причина скрытия необязательна. Удаление причины из предпочтений не возвращает предложение автоматически; скрытые предложения восстанавливаются отдельно. Отмена сразу после скрытия удаляет только что созданную причину и возвращает карточку.

На iPhone (iOS 16.4+) добавь сайт через Safari → «Поделиться» → «На экран Домой», открой с иконки, затем разреши push. Android предлагает установку из меню браузера. Офлайн доступна оболочка; приватные API-ответы не кешируются. Для изменений требуется сеть. Обновление приложения предлагается отдельным баннером.

## Эксплуатация и резервное копирование

```sh
docker compose ps
docker compose logs --tail=100 app worker
```

Настрой резервное копирование у провайдера MongoDB (например, snapshots) или используй MongoDB Database Tools (`mongodump` / `mongorestore`). URI бери из окружения, не вставляй пароль в команды, которые сохраняются в истории. Храни резервную копию БД и `.env` / `.env.secrets` раздельно в защищённом месте. Резервная копия содержит анкету, причины отказов, исходные сообщения и зашифрованную Telegram-сессию. Перед первым обновлением с несколькими аккаунтами останови старые app и worker, сделай резервную копию БД и сохрани прежние env-ключи. Старую версию нельзя запускать одновременно с новой во время миграции. Для обновления: резервная копия, `docker compose up -d --build`; проверка `/api/health`, логов worker и ручного сбора. Автоматическая очистка старых сообщений пока не реализована; учитывай рост БД.

## Следующий этап — Яндекс Календарь

В настройках есть только честно обозначенный будущий раздел. Реального чтения iCal сейчас нет. Следующая итерация: несколько секретных ссылок iCal, обновление раз в час и перед подбором, повторяющиеся события и исключения, учёт часовых поясов. Пересечения показываются предупреждением, не исключением; отсутствие времени или свежего календаря не означает «свободен». Запись событий в Яндекс не планируется.

## Проверка перед настоящим использованием

Старые данные из прежней SQL-версии автоматически не переносятся; эта версия использует отдельные коллекции MongoDB.

Автотесты проверяют API ленты/отказов, ограничения источников, CSRF, шифрование, пароль, базовый подбор и дедупликацию. Для полного приёмочного теста нужны настоящие MongoDB, ProxyAPI, Telegram и HTTPS-домен: авторизация/2FA, лимиты Telegram, живой ответ модели, ночной запуск, установка и доставка push на реальных телефонах. Эти интеграции нельзя подтвердить одними демоданными.
